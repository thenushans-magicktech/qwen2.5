# Teaching Qwen to design (no GPU, no training)

Qwen reads these files every time it designs a kitchen. To change how it designs,
edit them. The model itself is not changed, so there is no training step and no GPU is needed.

| File | What Qwen gets from it |
|---|---|
| `designer_playbook.md` | The designer's rules: zones, work triangle, layout choice, sizes. Sent as the system prompt. |
| `worked_examples.md` | Three rooms with the designer's thinking and decisions. Qwen copies the *way of thinking*. |
| `cabinet_guide.json` | What every catalogue category is for. The short notes (`prompt_note`, `combinations`, `width_notes`) appear next to each option Qwen can choose. |
| `CABINET_GUIDE.md` | Readable version of the guide with sizes from the catalogue. Generated by the tool; do not edit it. |

## How to teach Qwen something new

1. Edit the playbook, an example, or a note in `cabinet_guide.json`. Keep the text short:
   Small models follow short, concrete rules best, and every extra line slows each design on CPU.
2. Run `python design_knowledge.py` to regenerate `CABINET_GUIDE.md`.
   It also lists catalogue categories that have no note yet.
3. Run the tests: `python -m pytest test_pipeline.py -q`. They check that every option has a note
   and that the examples only use codes that exist in the catalogue.
4. Measure the effect: `python designer_benchmark.py --versions v2 --rooms compact big_U`.
   This takes about 2-4 minutes per room on a CPU laptop. The full benchmark compares
   `v2` (this knowledge) with `v1` (the original prompt) on 8 rooms and writes `benchmark/REPORT.md`.

The web server loads these files when it starts; restart it after editing.
Set `MAGICKHOME_PROMPT_VERSION=v1` to switch back to the original prompt.

## Where Qwen's choices go

Qwen only states its design intent: which walls get cabinets, which sink and hob units go where,
the tall units, the feature units, the wall-cabinet sizes, the water purifier and the display unit.
The rule engine then places every cabinet exactly. It enforces the sink under the window, door clearances,
corner cabinets, the chimney zone and zero collisions, and corrects Qwen when its intent breaks a rule.

Notes marked `"confirm": true` in `cabinet_guide.json` are my best understanding and need a
MagickHome designer to check them, for example the hob units "with flap down" and the low-height base unit.
